## 認証

- [ ] **`APP_ENV=local`（開発用の認証スキップ）が本番の設定に入っていない**
      `env.yaml` / `cos.env` / Cloud Run の環境変数を実際に見る。
      入っていると**誰でも管理者として入れる**。
      アプリは起動を拒否し `deploy-cos.sh` も弾くが、
      両方をすり抜ける経路（GCE で手動 `docker run` など）がありうる
- [ ] **本番の画面に開発モードのバナーが出ていない**
      出ていたら認証が効いていない。すぐ止める
- [ ] **ID トークンの検証で `aud`（クライアント ID）を渡している**
      省くと、別アプリ向けのトークンを受け入れてしまう
- [ ] **`iss` と `email_verified` を確認している**
      未確認メールを許すと、他人のメールを騙るアカウントが通る
- [ ] **自前のユーザーマスタで許可を確認している**
      Google アカウントは誰でも持てる。署名検証だけでは全世界に公開しているのと同じ
- [ ] **無効化したユーザーが即座に弾かれる**
      `resolve_user()` が `enabled` を見ている。退職者対応の要
- [ ] **`/healthz` 以外の全エンドポイントに `require_login` がある**
      grep で確認する: `rg "@router\.(get|post|put|delete)" -A3 backend/api | rg -v require_login`

## 認可

- [ ] **ロール名ではなく機能キーで判定している**
- [ ] **一覧を返すエンドポイントでも絞り込んでいる**
      詳細だけ守って一覧を素通しにすると、名前や件数から中身が推測される
- [ ] **フロントの出し分けとバックエンドの検査が両方ある**
      ボタンを隠すのは体験のため。利用者は URL も開発者ツールも使える
- [ ] **管理者が自分を締め出せない**
      自分の管理権限剥奪・自己無効化・自己削除を拒否している
- [ ] **権限チェックのテストがある**
      UI では確認できない箇所なので、テストでしか守れない

## セッションと Cookie

- [ ] **`APP_SESSION_SECRET` が環境変数から来ていて、開発用の値ではない**
      漏れると任意のユーザーになりすませる。最も重い秘密
- [ ] **worker / レプリカ間で同じ鍵を使っている**
      違うとリクエストごとにログアウトする
- [ ] **HTTPS 配信で `Secure` 属性が落ちていない**
      リバースプロキシで TLS 終端している場合は特に確認
- [ ] **`SameSite` を緩めていない**（既定は `Lax`）
      `None` にすると CSRF の経路が開く。緩めるなら CSRF トークンを別途入れる
- [ ] **状態を変える操作が GET になっていない**
      `<img src="/api/orders/1/delete">` で消せてしまう
- [ ] **JSON API が `Content-Type: application/json` を要求している**
      単純リクエストの form POST では JSON を送れないため、フォーム経由の CSRF が成立しない
- [ ] **ログアウトが `session.clear()`**
      個別キーの削除は消し漏れる

## HTTP レスポンスヘッダー

`fastapi-backend` の `core/security_headers.py` を入れていれば、
このうち大半は自動で付く。確認するのは「緩めていないか」のほう。

- [ ] **`SecurityHeadersMiddleware` を `main.py` のいちばん先に登録している**
      後から足したミドルウェアほど外側に来る。先頭に置くと、
      他のミドルウェアが返すエラー応答にもヘッダーが付く
- [ ] **`script-src` に `'unsafe-inline'` / `'unsafe-eval'` / `*` が入っていない**
      入れた瞬間に、CSP による XSS の緩和がほぼ意味を失う。
      `style-src` の `'unsafe-inline'` は Vuetify のために許容している
- [ ] **CSP に足した外部オリジンが、いま本当に使われている**
      検証のために足したまま残りやすい。使っていない許可は消す
- [ ] **`frame-ancestors 'none'` を外していない**
      外すとクリックジャッキングが成立する。埋め込みが必要なら、
      全許可にせず埋め込み元を列挙する
- [ ] **本番で `Strict-Transport-Security` が付いている**
      TLS を手前で終端する構成では `X-Forwarded-Proto` を見ないと付かない。
      `curl -I https://<本番URL>` で実際に確認する
- [ ] **`/api/*` に `Cache-Control: no-store` が付いている**
      付いていないと、権限を変えた直後に古い応答が返る
- [ ] **HTML に `must-revalidate` が付いている**
      キャッシュされると、デプロイしても利用者に古い SPA が出続ける
- [ ] **`tests/test_security_headers.py` が通っている**
      CSP を緩めたことに気付くための仕掛け。落ちたら緩めた理由を確認する

ブラウザの開発者ツールのコンソールに CSP 違反が出ていないかも見る。
**画面上は「読み込み中のまま止まる」ように見える**ことが多く、
エラーダイアログが出ないので気付きにくい。

## 秘密情報

- [ ] **`.env` が `.gitignore` に入っている**
- [ ] **`.env.sample` に実際の値が入っていない**（キー名だけ）
- [ ] **`env.yaml` / ConfigMap に秘密が入っていない**
      入れてよいのはプロジェクト ID やモデル名など、漏れても困らないものだけ
- [ ] **本番の秘密が Secret Manager / k8s Secret 経由**
- [ ] **`.dockerignore` が `.env` と `backend/data` を除外している**
      イメージに焼き込まれると、レジストリにアクセスできる全員に漏れる
- [ ] **例外メッセージに秘密が混ざっていない**
      接続文字列や API キーを含む例外をそのまま返していないか
- [ ] **秘密をコミットしたことがあるなら、ローテートした**
      履歴から消すだけでは足りない。既に取得された前提で扱う

確認コマンド:

```bash
git log -p --all -S "AIza" -- . | head       # API キーらしき文字列の混入
docker run --rm -it myapp:dev sh -c 'ls -la /app/backend | grep -i env'
```

## 入力の扱い

- [ ] **フロントの検証と同じ検証がバックエンドにもある**
      フロントの検証は入力補助であって防御ではない
- [ ] **パス・ファイル名になる値を文字集合で制限している**
      `../..` でファイルシステムを辿られる
      ```python
      if not re.fullmatch(r"[A-Za-z0-9_-]{1,64}", identifier):
          raise ValueError("識別子の形式が不正です。")
      ```
- [ ] **SQL を組み立てるならパラメータ化している**
      文字列連結で組み立てない。BigQuery なら `ScalarQueryParameter`
- [ ] **ログイン後のリダイレクト先を検証している**
      `//evil.example.com` はスキーム相対 URL で外部に飛ぶ。`/` 始まりの確認だけでは不足
- [ ] **アップロードを受けるなら、サイズ上限と拡張子・MIME を検証している**
      拡張子だけでは不十分。中身も確認する
- [ ] **数値・件数のパラメータに上限がある**
      `limit=99999999` でメモリを食い潰される

## 出力の扱い（XSS）

- [ ] **`v-html` に渡す文字列の出所が分かっている**
      自前バックエンドが生成した Markdown なら可。利用者入力・外部データ・
      LLM 出力が混ざるなら DOMPurify を通す
- [ ] **HTML テンプレートに値を埋めるとき、JS 文字列として安全に埋めている**
      `json.dumps()` を通す（`login.html` のプレースホルダ置換がこの形）
- [ ] **エラーメッセージに利用者入力をそのまま含めていない**
      含めるなら、必ずエスケープされる経路（JSON レスポンス）に限る

## 外部への通信（SSRF）

利用者が指定した URL にサーバから接続する機能（Webhook 設定、URL 取り込み）がある場合。

- [ ] **接続先を許可リストで制限しているか、少なくとも内部アドレスを弾いている**
      `169.254.169.254`（メタデータサーバ）に到達できると、
      クラウドの認証情報を抜かれる
- [ ] **リダイレクトを追わない、または追った先も検証する**
- [ ] **タイムアウトを設定している**
      無いと、応答しない相手にワーカーが占有される

## 依存関係とコンテナ

- [ ] **`pip list --outdated` / `npm audit` を確認した**
- [ ] **ベースイメージが最新のパッチ版**
- [ ] **ビルドツールが最終イメージに残っていない**（多段ビルドになっている）
- [ ] **不要なポートを `EXPOSE` していない**
- [ ] **`--allow-unauthenticated` にしている場合、アプリ側の認証が確実に効いている**
      Cloud Run を公開にするなら、アプリの認証が唯一の防御線になる

## ログと個人情報

- [ ] **アプリケーションログにメールアドレスを載せていない**（`user_id_hash` を使う）
- [ ] **監査ログの閲覧が管理者限定**
- [ ] **パスワードやトークンをログに出していない**
      リクエスト本文をそのままログに出す実装になっていないか
- [ ] **スタックトレースを利用者に返していない**
      内部構造の露出になる。ログにだけ残す
