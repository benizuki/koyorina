## 言語の使い分け

| 対象 | 言語 |
|---|---|
| 変数名・関数名・ファイル名・コミットの型（feat/fix など） | 英語 |
| 利用者に表示されるメッセージ、UI ラベル | 日本語 |
| コード内コメント、docstring、README | 日本語 |
| ログの `message` フィールド | 英語（機械が読む前提。grep しやすい） |

利用者が非エンジニアなので、画面に出る文字は日本語で統一する。
一方でコード側を日本語にすると補完も検索も効きが落ちるため、そこは英語のままにする。

## エラーメッセージ

利用者に返すメッセージは「**次に何をすればよいか**」を書く。
技術的な原因はログに書き、画面には出さない（内部構造の露出にもなる）。

```python
# 悪い: 利用者に何をしてほしいのか分からない
raise HTTPException(status_code=403, detail="permission denied")

# 良い: 誰に頼めばよいかまで書く
raise HTTPException(
    status_code=403,
    detail={
        "error": "この操作にはレポート権限が必要です。管理者に権限の付与を依頼してください。",
        "your_role": current_role(request),
    },
)
```

エラーレスポンスの形は 1 つに揃える。フロント側の分岐が減る。

```json
{ "error": "利用者向けの日本語メッセージ", "status_code": 403 }
```

## コメント

**何をしているか**ではなく、**なぜそうしたか**を書く。
コードを読めば分かることを日本語で繰り返しても、更新されずに嘘になるだけ。

```python
# 悪い
# ユーザーを取得する
record = get_user(email)

# 良い
# 無効化済みユーザーは None を返す。ここで弾かないと、退職者のセッションが
# 残っている間だけログインできてしまう。
record = resolve_user(email)
```

## 環境変数

`backend/config/settings.py` の `Settings` クラス 1 箇所に集約する。
`os.getenv` をアプリ各所に散らすと、必要な設定の全体像が分からなくなり、
デプロイ時に「その環境変数を入れ忘れていた」で必ず落ちる。

- **必須の設定は `os.environ["KEY"]`** — 起動時に落とす。動いてから気付くより早い
- **任意の設定は既定値付きヘルパ** — `_env_str` / `_env_flag` / `_env_csv`
- **`.env.sample` を必ず更新する** — 新しい環境変数を足したら同じ PR で追記する
- **`.env` は絶対にコミットしない** — `.gitignore` に入っていることを確認

## 永続データ

`backend/data/` 配下に置き、`.gitignore` する。本番ではボリュームをマウントする。

- 設定・マスタ系（ユーザー、グループ）→ `*.json`、全体を読んで全体を書く
- 追記される記録（監査ログ、実行履歴）→ `*.jsonl`、1 行 1 レコード、サイズでローテート
- 複数プロセスから書くなら `threading.Lock` では足りない。その時点で外部ストアに移す

書き込みは「読む → 変える → 全部書く」を 1 つのロックの中で行う。
部分更新をやろうとすると壊れたときに復旧できない。

## ログ

構造化 JSON を 1 行で標準出力に出す。Cloud Logging も k3s のログ基盤もこれで拾える。

```python
logger.info(json.dumps({
    "severity": "INFO",
    "message": "report generated",
    "event": "report.generate",
    "user_id_hash": user_id_hash,   # メールアドレスそのものは載せない
    "elapsed_ms": elapsed_ms,
}, ensure_ascii=False))
```

- **個人情報は原則ハッシュ化**。監査ログだけは追跡のためメールを残してよいが、
  アクセスは管理者権限に限定する
- **`severity`** を入れると Cloud Logging がそのまま重大度として扱う
- **高頻度のポーリング API はアクセスログから除外**する。ノイズで本物のエラーが埋もれる

## README に書くこと

異動してきた人が README だけで動かせる状態にする。最低限これ。

1. 何をするアプリか（3 行）
2. ローカル起動手順（backend / frontend の 2 コマンド）
3. 必要な環境変数の一覧と取得方法
4. デプロイ手順（コマンド 1 つ）
5. ユーザーの追加方法（誰がどうやって権限を付けるか）
6. よくある障害と対処
