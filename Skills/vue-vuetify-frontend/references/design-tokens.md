# 見た目を揃える（デザイントークン）

画面を足すたびに配色・文字サイズ・余白が少しずつずれていく、を防ぐための取り決め。
値は `src/styles/tokens.css` に、共通部品は `src/styles/base.css` にある。

## なぜトークンにするか

コンポーネントに生の値を書くと、破綻の仕方が決まっている。
実際に起きた例を挙げる。

- **文字サイズ** — 1 つのアプリ内で `11 / 12 / 13 / 14 / 15 / 16 / 17 / 18 / 19 / 21 / 22 / 25px`
  の 12 種類が使われ、しかも「一覧は 13px、ダイアログの同じ一覧は 12px」のような
  不揃いが残った。直すために、全画面のセレクタへ `font-size: 13px` を当てる
  ファイルを 260 行書くことになった
- **角丸** — `4 / 5 / 6 / 7 / 8 / 9 / 10 / 11 / 12px` の 9 種類。
  隣り合うカードの角丸が 1px 違う、という状態が生まれる
- **余白** — `3 / 4 / 5 / 6 / 7 / 8 / 9 / 10 / 12 / 14px`。
  同じ意味の隙間が場所ごとに違う
- **チップ** — `padding: 3px 7px` / `0 8px` / `5px 8px` / `5px 10px 5px 6px` が併存し、
  横に並べると高さが揃わない

いずれも、1 つ 1 つの判断は妥当に見える。**その場では 1px の違いに気付けない**のが
問題で、積み上がってから直そうとすると全画面の修正になる。
段を先に決めておけば、迷う余地がなくなる。

## 色

役割で名前を付けている。`--teal-500` のような色そのものの名前にしない。
そうしておくと、配色を変えるときに `tokens.css` だけ差し替えれば済む。

| 種類 | トークン | 使いどころ |
|---|---|---|
| 文字 | `--ink-1` 〜 `--ink-4` | 番号が上がるほど控えめ。1=見出し、2=本文、3=説明、4=ラベル |
| 文字 | `--ink-muted` | **文字に使わない。** AA を満たさない。区切りや装飾専用 |
| 文字（状態） | `--text-brand` `--text-warn` `--text-danger` `--text-info` | 同名の `--surface-*` と対で使う |
| 文字（濃色の上） | `--text-on-solid` `--text-on-inverse` | 塗りつぶし・反転面の上 |
| 面 | `--surface-page` `--surface-card` `--surface-subtle` `--surface-muted` `--surface-raised` | 地 → カード → カード内の段差 |
| 面（状態） | `--surface-accent` `--surface-warn` `--surface-danger` `--surface-info` | 薄い色面。文字は対応する `--text-*` |
| 面（塗り） | `--surface-*-solid` | 濃い塗り。文字は `--text-on-solid` |
| 罫線 | `--border-subtle` `--border-default` `--border-mid` `--border-brand` ほか | subtle=表の行区切り、default=カードと入力欄 |

**`--ink-1` 〜 `--ink-4` は、どの `--surface-*` の上でも WCAG AA（4.5:1）を満たす。**
この保証があるので、「この背景だと薄すぎないか」を毎回確かめなくてよい。
状態の文字（`--text-brand` など）も、同じ状態の薄い面とカード面の両方で AA を満たす。
`--text-on-solid`（白）は、すべての `--surface-*-solid` の上で AA を満たす。

```bash
npm run check:contrast
```

**色を変えたら必ず走らせる。** light / dark の全組み合わせを検査し、
1 つでも 4.5:1 を割ると終了コード 1 で落ちる。
この保証が崩れると、画面ごとに濃さを確かめる作業が復活する。

**状態の色は 3 つに絞る。** brand（正常・完了）、warn（注意・未確定）、danger（エラー・破壊的操作）。
info は情報の補足にだけ使い、状態には使わない。増やすと利用者が意味を覚えられない。

### ライトとダークを 1 行で持つ

色は `light-dark(ライト値, ダーク値)` で書く。

```css
:root {
  color-scheme: light dark;                       /* これが切り替えの土台 */
  --ink-1: light-dark(#20343a, #eef4f2);
}
:root[data-theme="light"] { color-scheme: light; }
:root[data-theme="dark"]  { color-scheme: dark; }
```

| `<html>` の状態 | 効くテーマ | 誰が付けるか |
|---|---|---|
| 属性なし（**既定**） | **OS の設定に従う** | — |
| `data-theme="light"` | 常にライト | `useThemeMode()` / `theme-init.js` |
| `data-theme="dark"` | 常にダーク | 同上 |

**別ブロックに分けないのは、片方だけ足す事故を防ぐため。**
`:root` と `:root[data-theme="dark"]` に分けると、トークンを増やしたときに
片方へ書き忘れ、もう一方のテーマでその色が未定義になる。
CSS は未定義の変数を無視するので、**エラーにならず色だけ消える**。
1 行にまとめれば、書き忘れは構文エラーになる。

`color-scheme` を宣言していることで、**スクロールバー・ネイティブの日付ピッカー・
フォーム部品など、ブラウザ側が描くものも一緒に切り替わる。**
ここを揃えないと、暗い画面に白いスクロールバーが出る。

サイズ・余白・角丸はテーマで変えない。変えると同じ画面が別物になり、
片方のテーマでしか確認されていないレイアウト崩れが生まれる。

明暗を単純に反転しない。ダークでは彩度を上げないと沈むので、
`--text-brand` は明るい側に振ってある。両方のテーマで実際に見て決めること。

**必要ブラウザ: Chrome 123+ / Edge 123+ / Safari 17.5+ / Firefox 120+。**
これより古い環境が対象なら `light-dark()` をやめ、`:root` /
`@media (prefers-color-scheme: dark)` の `:root:not([data-theme="light"])` /
`:root[data-theme="dark"]` の 3 ブロックに展開する。
値が 3 か所に散るので、トークンを増やすときは全部に足すこと。

### 切り替えの実装

`useThemeMode()` が `system` / `light` / `dark` の 3 状態を持ち、
`<html>` の `data-theme` を付け外しして `localStorage` に保存する。

**既定は `system`。** 端末をダークにしている人が、何も操作せずダークで開けるようにするため。
2 状態だけだと必ずどちらかを押させることになる。

```ts
const { mode, effectiveTheme, setMode, cycleMode } = useThemeMode()
```

3 か所を合わせる必要がある。1 つ欠けると中途半端に切り替わる。

| 何を | どこで | 欠けるとどうなる |
|---|---|---|
| `data-theme` 属性 | `useThemeMode()` | CSS 変数が切り替わらない |
| Vuetify のテーマ名 | `App.vue` の `watch` | `v-card` だけ明るいまま残る |
| 起動前の復元 | `public/theme-init.js` | 読み込み時に一瞬ライトで描かれる |

**ちらつき対策をインラインスクリプトで書かないこと。**
`core/security_headers.py` の CSP が `script-src 'self'` なので、
インラインの `<script>` はブラウザに実行を拒否される。
同一オリジンの `.js` ファイルとして `public/` に置けば通る。

「システムに従う」を選んでいるときは `theme-init.js` は何もしない。
`color-scheme: light dark` が OS の設定を拾うので、
**JavaScript 抜きで正しい色から描き始められる。**

## 文字サイズ

7 段だけ。ここに無いサイズを使いたくなったら、まず既存の段で足りないかを疑う。

| トークン | 値 | 用途 |
|---|---|---|
| `--fs-2xs` | 11px | 単位、グラフの軸ラベル |
| `--fs-xs` | 12px | 補足、タイムスタンプ、チップ |
| `--fs-sm` | 13px | 一覧・フォーム・表の既定 |
| `--fs-md` | 14px | 本文の既定（`body` の値） |
| `--fs-lg` | 16px | カード・パネルの見出し |
| `--fs-xl` | 20px | 画面見出し |
| `--fs-2xl` | 25px | KPI などの数値 |

業務画面は情報量が多いので、**読ませる文章は 14px、密度が要る部分は 13px** に寄せる。
一覧の中だけ 12px にしたくなったら、それは行の高さか余白の問題であることが多い。

行間は `--lh-tight`（1.45／見出し）、`--lh-normal`（1.65／本文）、
`--lh-relaxed`（1.8／チャットなどの長文）の 3 段。

太さは `--fw-normal` (400) / `--fw-medium` (500) / `--fw-bold` (700) の 3 段だけ。
**600 や 750 を混ぜない。** 可変フォントでないと再現されず、
環境によって太さが変わる。

## 余白・角丸・部品の高さ

- **余白は 4px 刻み**（`--sp-1` = 4px 〜 `--sp-10` = 40px）。
  `gap` も `padding` も `margin` もこの段から選ぶ。5px や 7px を使わない
- **角丸は 4 段**。`--radius-sm` (6px) 入力欄・チップ、`--radius-md` (10px) カード内のブロック、
  `--radius-lg` (14px) カード・ダイアログ、`--radius-pill` は**状態バッジ専用**
- **部品の高さは 3 段**。`--control-sm` (32) / `--control-md` (40、既定) / `--control-lg` (48)。
  ボタンと入力欄を横に並べたときに 1px ずれる、を防ぐための基準

角丸を pill にするかどうかで意味を分けているのが効く。
**丸い＝いまの状態、角丸＝分類ラベル**、と形で読み分けられる。

## チップ

状態や分類を示す小さなラベル。`base.css` の `.chip` を使う。

```vue
<span class="chip chip--warn">未確定</span>
<span class="chip chip--pill chip--brand">承認済み</span>
<span class="chip chip--sm">v3</span>
```

| クラス | 高さ | 文字 | 使いどころ |
|---|---|---|---|
| `.chip--sm` | 20px | 11px | 表のセル内、他の文字に添える |
| `.chip`（既定） | 24px | 12px | 一覧の行、カードのヘッダ |
| `.chip--lg` | 28px | 13px | 画面見出しの隣、単独で置く |

色は `--brand` `--warn` `--danger` `--info` `--solid`。無指定は中立（灰）。

**Vuetify の `v-chip` と混ぜない。** どちらか一方に寄せる。
両方使うと、同じ行に高さの違うチップが並ぶ。`v-chip` を使う場合は
`main.ts` の `defaults.VChip` で `size` と `variant` を固定してあるので、
呼び出し側で `size` を書かないこと。

## 補足枠（tip）

「この操作の注意点」「なぜ選べないのか」を画面に常設するための枠。

```vue
<p class="tip tip--warn">
  <v-icon icon="mdi-alert-outline" />
  <span>公開すると、閲覧権限のある利用者全員に見えます。</span>
</p>
```

| クラス | 余白 | 文字 | 使いどころ |
|---|---|---|---|
| `.tip`（既定） | 12px | 13px | フォームやカードの下に添える |
| `.tip--compact` | 8/12px | 12px | 表のセル内、ダイアログの脚注 |

色は `--brand` `--warn` `--danger`。無指定は中立。

**`v-alert` と使い分ける。** `v-alert` は「いま起きたこと」を伝える通知で、
閉じられる前提。常設の説明に使うと、閉じるボタンの有無が画面ごとにぶれる。
常設の説明は `.tip`、操作の結果は `v-alert` と決めておく。

## Vuetify 側で揃える

**見た目を揃えるいちばん確実な方法は `main.ts` の `defaults` に書くこと。**
画面ごとに `variant` や `density` を書かせると、必ずばらける。

```ts
defaults: {
  VBtn:       { rounded: 'lg', elevation: 0, variant: 'flat' },
  VCard:      { rounded: 'lg', elevation: 0, border: true },
  VTextField: { variant: 'outlined', density: 'comfortable', hideDetails: 'auto' },
  VDataTable: { density: 'comfortable', itemsPerPage: 20 },
  VChip:      { size: 'small', variant: 'tonal' },
  VAlert:     { density: 'compact', variant: 'tonal' },
}
```

`hideDetails: 'auto'` は特に効く。付けないと、エラーが無いときも
説明文用の高さが確保され、フォームの行間が画面ごとにずれる。

呼び出し側で `defaults` を上書きしたくなったら、
**「本当にその画面だけ違ってよいか」を先に疑う。**
たいていは `defaults` のほうを直すべき場面になっている。

### Vuetify のテーマ色と CSS トークンの二重管理

Vuetify は `on-primary` などを自前で計算するため、テーマ色は hex で渡す必要がある。
そのため `main.ts` の `themeColors` と `tokens.css` に同じ値が 2 か所出る。

**hex を書いてよいのはこの 2 ファイルだけ。** 対応関係はコメントで併記してある。
片方だけ変えると、`v-btn` の色と手書き CSS の色が少しずつ違う画面ができる。

## トークンを足すとき

1. **既存の段で足りないかを先に確認する。** 「もう少し小さい」で `--fs-3xs` を
   足し始めると、段が意味を失う
2. **役割で名前を付ける。** `--fs-dialog-note` ではなく、既存の `--fs-xs` を使う。
   役割が本当に新しいときだけ足す（例: `--surface-selected`）
3. **`light-dark()` で両方の値を書く。** 片方だけだと構文エラーになるので、
   書き忘れがその場で分かる。色をテーマで変えないなら hex をそのまま書いてよい
   （`--text-on-solid` など）
4. **1 画面でしか使わない見た目は `base.css` に入れない。**
   そのコンポーネントの `<style scoped>` に書く。`base.css` に入れてよいのは
   3 画面以上で使うものだけ

## 既存アプリに後から入れる

一度に全部置き換えようとしない。壊れたときに原因が分からなくなる。

1. `tokens.css` を追加し、`main.ts` の先頭で読む（この時点では何も変わらない）
2. **色から始める。** 既存の hex を grep で拾い、近い値ごとにまとめてトークンに割り当てる。
   完全一致でなくてよい。「この 5 つは全部 `--border-default` でよい」と束ねる
3. `main.ts` の `defaults` を入れる。ここで一気に揃うので、効果が見えやすい
4. **文字サイズは最後。** 影響範囲が広く、詰まって見える／間延びして見えるの
   判断が要る。画面単位で、実際に見ながら移す

2 の「近い値ごとに束ねる」を惜しむと終わらない。
`#e0e6e1` と `#e0e6e2` を別トークンにしても、誰も違いを認識できない。
